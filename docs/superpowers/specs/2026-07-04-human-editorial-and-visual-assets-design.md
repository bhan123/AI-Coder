# AI 内容人格化与自动配图设计

日期：2026-07-04  
状态：已确认，待实施计划

## 1. 背景

`ai_content_loop` 已能完成检索、评分、Hermes 写稿、四平台正文生成、人工审阅和版本恢复，但文章仍像工具说明书：结构过于整齐，缺少判断、场景和自然笑点；公众号成品也没有封面和正文插图。

本次设计同时解决“内容像谁写”和“文章配什么图”。图片只能放大文章气质，不能单独拯救一篇干巴的正文。

## 2. 目标

- 人格固定为“懂技术的损友 70% + 好奇实测派 30%”。
- 每篇有 2–4 个自然笑点，重点前置，有明确判断，不靠虚假夸张。
- 没有试跑证据时不伪造第一人称体验。
- 每篇公众号稿自动生成一张封面和一张正文插图。
- 视觉采用原创互联网梗图，不抓取影视截图、明星脸或第三方表情包。
- 在腾讯云 Lighthouse 4 核 8G 上稳定运行，不部署本地生图模型。
- 图片、截图或远程生图失败时自动回退，不能阻塞审阅。
- 正文和图片都支持预览、换版、版本保存和历史恢复。

## 3. 非目标

- 本阶段不自动发布，不生成视频、动图、长图或小红书多页卡片。
- 不建立无限增长的热梗爬虫，不训练私有生图模型。
- 不删除模型或平台写入的 AI 标识，不把自动生成内容伪装成纯人工内容。

## 4. 核心决策

### 4.1 事实与表达分层

流水线拆为两个阶段：

1. **事实稿**只负责正确，严格引用事实包、来源和试跑结果。
2. **损友编辑**只负责表达，可以调整节奏、加入比喻、吐槽和作者判断，但不能修改数字、功能、价格、许可和来源。

不使用无约束的“去 AI 味重写”。编辑阶段必须携带锁定事实清单，质量失败时最多自动修订一次。

### 4.2 混合图片架构，模板优先

素材优先级：

1. 安全试跑产生的真实截图。
2. 许可证明确允许使用的官方项目图片。
3. 自有表情、图标、几何人物和原创模板。
4. 腾讯混元生成的无字底图。
5. 纯模板兜底图。

混元是增强能力，不是唯一依赖。所有中文标题、梗句和批注由本地模板引擎叠加。

### 4.3 不可变资产与人工审核

重新生成图片会创建新版本，不覆盖已被正文引用的文件。前 30 天正文和图片都需人工审核；`approved` 状态仍不自动发布。

## 5. 端到端流程

```text
检索与评分
  -> 事实包
  -> 可选安全试跑
  -> 事实稿
  -> 损友编辑
  -> 内容质量检查
  -> 视觉简报
  -> 截图/素材选择
  -> 模板渲染或混元底图
  -> 图片质量检查
  -> final JSON + 不可变图片资产
  -> 审阅台
  -> 人工批准
```

事实包至少记录来源、可引用数据、许可、限制、试跑状态、截图和日志引用。只有试跑成功，正文才能出现“我试了一下”等体验表述。

## 6. 内容人格与写作规则

公众号版本约 700–1000 字，采用五段节奏：

1. 用具体场景、反差或吐槽开场，不用“你有没有发现”。
2. 前 100 字给出是否值得关注、适合谁和最大代价。
3. 用生活化比喻解释工具，不逐句翻译 README。
4. 只讲两个最有意思、证据充分的场景。
5. 用一个诚实的坑和一个可执行动作收尾。

标题允许悬念、反差和吐槽，但禁止虚构收益、效率和用户数据，禁用“震惊”“彻底颠覆”“人人都能月入过万”等表达。

质量检查限制：

- “在这个数字化时代”“赋能”“值得一提的是”“总的来说”等套话。
- “无论你是学生、职场人、创作者还是老板”式受众清单。
- 过度整齐的三段排比、相同句长和密集小标题。
- Emoji 和感叹号各不超过 3 个。
- 每篇 2–4 个自然笑点；不为凑数量机械插梗。
- 必须有一个作者判断，不能全程端水。

## 7. 视觉简报与图片规格

Hermes 随正文输出结构化视觉简报：

```json
{
  "angle": "expectation_vs_reality",
  "cover_line": "AI 写完代码，人类打开测试",
  "cover_subline": "笑容不会消失，只会转移",
  "body_panels": [
    {"label": "AI 写完代码", "reaction": "自信"},
    {"label": "你打开测试", "reaction": "沉默"}
  ],
  "template_hint": "ai_done_vs_tests",
  "source_asset_candidates": []
}
```

输出规格：

- 公众号封面：`900 x 383` JPEG，约 `2.35:1`，核心内容位于中央安全区。
- 正文插图：`1080 x 608` PNG，约 `16:9`，默认放在一句话结论之后。
- 封面目标小于 1 MB，正文图目标小于 2 MB，超出时自动压缩。

公众号封面比例参考 [Canva 微信公众号尺寸说明](https://www.canva.cn/sizes/wechat-official-account/)。

首批六个原创模板：

1. `boss_vs_worker`：老板视角 vs 打工人视角。
2. `expectation_vs_reality`：预期 vs 现实。
3. `ai_done_vs_tests`：AI 写完了 vs 测试打开了。
4. `before_vs_after`：使用前 vs 使用后。
5. `do_vs_dont`：能让它干什么 vs 别让它干什么。
6. `one_line_verdict`：一句话判决卡。

模板可以借用热门梗的语言结构，但不复制第三方图片。

## 8. 渲染与混元

首版本地渲染器采用 Python Pillow，并固定中文字体和原创图形资产。它负责中文换行、字号缩放、安全区、截图裁切、文字对比度、格式导出和压缩。

需要特殊人物或场景时，通过 provider 接口调用腾讯混元生成无字底图；服务器不运行本地图像模型。结果必须立即保存到本地，不能长期依赖临时外链。

当前能力依据：

- [腾讯混元生图产品概述](https://cloud.tencent.com/document/product/1668/86244)
- [混元生图 3.0 API](https://cloud.tencent.com/document/api/1668/124632)
- [免费额度](https://cloud.tencent.com/document/product/1668/90897)

## 9. 数据模型

`out/final/*.json` 继续作为正文和当前资产引用的唯一事实源，新增：

```json
{
  "editorial_profile": {
    "version": "tech_friend_v1",
    "persona": "tech_friend",
    "humor_level": "light",
    "verified_trial": false,
    "trial_artifact_refs": [],
    "quality_warnings": []
  },
  "visual_brief": {
    "angle": "expectation_vs_reality",
    "template_hint": "ai_done_vs_tests",
    "cover_line": "...",
    "cover_subline": "...",
    "body_panels": []
  },
  "visual_assets": {
    "cover": {
      "asset_id": "cover-wechat",
      "revision": "sha256-prefix",
      "path": "assets/<article-id>/<revision>/cover-wechat.jpg",
      "template": "ai_done_vs_tests",
      "ai_generated": false
    },
    "body": [
      {
        "asset_id": "body-01",
        "revision": "sha256-prefix",
        "path": "assets/<article-id>/<revision>/body-01.png",
        "ai_generated": false
      }
    ]
  }
}
```

路径必须相对于 `out/`，客户端不能提交绝对路径。公众号 Markdown 使用受控标记：

```text
{{asset:body-01}}
```

审阅者可以移动标记，预览器把它解析为当前图片。未来发布适配器上传正文图后再替换为平台 URL；当前阶段不调用发布接口。

资产布局：

```text
out/assets/<安全文章标识>/<不可变版本>/
├── cover-wechat.jpg
├── body-01.png
└── manifest.json
```

manifest 记录哈希、尺寸、模板版本、素材来源与许可、生图 provider、模型、任务 ID、seed、提示词摘要和 AI 状态。不得记录密钥、完整内部提示词或无关个人数据。

## 11. 审阅台

新增：

- 封面和正文实际插入位置预览。
- 图片来源、AI 状态和试跑证据提示。
- `换一句梗`：只修改图片文字并创建新版本。
- `换模板`：保留文案，重新排版。
- `重新生成底图`：明确提示会产生远程调用。
- `采用此版本`和正文、图片联合历史恢复。

本地模板渲染可同步完成；混元任务进入后台队列并由页面轮询，不能占住 Gunicorn 请求线程。正文和两张图片都通过校验后才能批准。

## 12. 安全、版权与合规

- 外部下载只允许 HTTP/HTTPS 和域名白名单，并限制大小、时间、重定向和像素。
- 同时校验 MIME 与实际格式，拒绝脚本 SVG、HTML 伪装图片和未知格式。
- 许可为 `unknown` 的图片不自动进入发布资产。
- 官方 logo 只用于项目识别，不修改标志，不暗示合作或背书。
- 腾讯云密钥仅存于服务器 `0600` 环境文件或密钥服务，不进入日志、manifest、历史或 API。

目标是降低机械化表达，不是隐瞒 AI 参与。系统保留 `ai_generated`、provider、模型和任务记录，不删除显式或隐式标识。相关依据：

- [国家网信办《人工智能生成合成内容标识办法》答记者问](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)

## 13. 失败处理

| 失败 | 行为 |
|---|---|
| 损友编辑失败 | 保留事实稿和 `needs_human_review`，追加 `editorial_rewrite_failed` 警告 |
| 出现无证据第一人称实测 | 质量失败，最多修订一次 |
| 官方素材许可未知 | 跳过素材 |
| 试跑截图失败 | 使用原创信息卡 |
| 混元失败或额度不足 | 回退原创模板 |
| 文字溢出 | 缩小字号；仍失败则缩短文案重绘 |
| 资产写入失败 | 不修改 final JSON 和当前资产引用 |
| 浏览器并发修改 | 沿用版本摘要冲突机制，拒绝旧版本覆盖 |

任何失败都不得损坏当前正文、图片或历史版本。

## 14. 测试与上线

测试覆盖：

- 锁定事实、实测证据、套话和标题规则。
- 视觉简报结构、六个模板选择和中文换行。
- 图片尺寸、压缩、哈希、manifest 和路径安全。
- 外部素材限制、混元超时和模板回退。
- CLI 生成、审阅 API、联合历史恢复、权限与 CSRF。
- 六个模板的固定字体快照测试。
- 浏览器中的预览、换梗、换模板、后台任务和恢复流程。

上线分三步：

1. 上线人格、质量检查、六个模板和审阅能力，不依赖混元。
2. 增加安全试跑、截图和混元 provider。
3. 累计约 30 篇数据后，按结构重写比例、换图次数、回退比例、打开率、读完率和分享率淘汰差模板。

## 15. 部署约束

- 继续使用 Lighthouse Ubuntu 4 核 8G。
- 本地渲染并发为 1。
- 图片初期存储在 `/opt/ai-content-loop/out/assets`。
- 只有当规模或备份成本成为实际问题时再迁移腾讯云 COS。
- 每日生成 timer 继续独立于审阅 Web 服务。

## 16. 验收标准

- 每篇公众号稿自动产生一张 `900 x 383` 封面和一张 `1080 x 608` 正文图。
- 图片失败时始终有原创模板兜底。
- 无成功试跑证据时不出现第一人称实测。
- 正文符合已确认的人格、篇幅和幽默规则。
- 审阅者可以预览、换梗、换模板、采用版本和恢复历史。
- 所有图片都有来源与 AI 状态记录。
- 现有正文、审核状态、定时器和登录安全能力不退化。
- 前 30 天不会自动发布。
