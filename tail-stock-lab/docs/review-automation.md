## 自动报告

- 独立于选股扫描器，读取正式 live / scheduled / tradable 信号，原策略与源库不写入。
- 按上海时间：周一至周五16:30起生成日报，周五18:00起生成周报（周一至周五）。尚未核验交易日历：节假日可能归档“无运行证据”，不能称为扫描失败。
- 默认处理最近7个自然日内已到期的日报和周报。重启后补跑此窗口；更早历史用已有显式日期补采/生成命令。参数 `--lookback-days` 支持1–31。
- V1跨假期接续：检查正常窗口之前31天的正式V1推荐，只为下一计划交易日落在本窗口的实际事件追加日报/已到期周报；补采后归档新修订，旧报告保留。已覆盖春节前推荐到节后首日收盘、重复运行幂等的集成测试。此限制覆盖目前支持的2026年已公布假期，不等于无限期离线恢复。运行记录的 `v1_carryover_windows` 列出追加区间；`--plan` 不读源库，因此仅打印基础排期，不含这类数据依赖的接续窗口。
- 每次先补采收盘（默认最多50只），再归档两种策略的统计、摘要及逐股分析。失败或批量上限未处理完时状态为 partial，仍归档未知结果，不伪造收盘。已有相同内容复用原报告；证据变化产生新修订。
- `review_scheduler.db` 保存运行记录与15分钟租约；重叠运行跳过，超时进程不能继续归档，后续运行接管。成功/部分失败后至少15分钟再执行。正常检查安排在16:00–23:45，每15分钟一次，实际完成时间受行情响应、批次和冷却影响。
- 内部CLI在Linux限制540秒，systemd外层600秒。中断留下超时租约可续行；只记录错误类别，不保存可能含密钥的异常正文。
- 独立数据文件：`review_evidence.db`、`review_collection.db`、`review_reports.db`、`review_scheduler.db`，均位于源库同目录；路径或硬链接冲突会拒绝。
- `GET /api/review/automation` 只读返回最近10次执行记录。运行完成不代表结果全部已知，也不能证明systemd定时器仍然启用。页面没有公网启动/改写接口。
- 报告发布到站内“报告归档”，不是邮件/消息推送。没有接入邮件、微信等发送渠道。

backend目录下预检（只打印排期，不开数据库、不请求行情）：

```sh
python scripts/run_review_reports.py --plan
```

在现有服务器已更新容器内单次执行（写独立衍生库并请求行情；不在本机部署）：

```sh
python scripts/run_review_reports.py --lookback-days 7 --max-jobs 50
```

## 显式复核已有收盘记录

在backend目录或已更新容器中按正式信号日期范围执行（会请求行情并写独立证据/队列库，非只读预检）：

```sh
python scripts/collect_review_closes.py --date-from 2026-09-04 --date-to 2026-09-04 --max-jobs 50 --recheck-completed
```

- 不加新选项时仍跳过已完成项；加选项时也会处理原来未完成的任务。限定日期是正式推荐/预警日期：除推荐当日外，V1自动加入日历可确定且日期已到的下一计划交易日目标；尚未来到的日期不入队，目标日16:00前不请求行情。同股票/目标日期继续去重复用。
- 先完成未完成任务，再优先较久未核对的已完成记录；批量上限防止单次无界请求。此选项是滚动复核，不是一次性有完成标志的复核批次：重复执行会继续轮换检查，自动周期排期尚未启用。
- 新行情严格匹配股票、日期和来源；空结果、错归属和错误类型按失败记录，不冒充成功。失败冷却15分钟，正在运行的租约不抢占。
- 变化追加修订，相同内容复用原证据。复核失败不删除旧证据，原历史报告不改写。重采后需重新运行报告生成器或由后续报告工作器生成新修订，CLI本身不会发布报告。
- 源库不迁移、不改写，没有新增公网写接口；该命令不安装/启用任何timer，也不能恢复原来未保存的历史触板时刻。

## 逐股原因分析

计算版本0.6.0，推荐当日解释版本1.0.2，V1次日解释版本1.0.0。使用已存证据规则，不调用大模型、不读取社区、不自动调参或交易。

- **当时为什么触发**：原始首次run的reason、因子值/分数/描述；不拿当前阈值冒充旧版本规则。
- **后来发生什么**：正式收盘优先，缺失时展示末次盘中观测并明确非收盘；读取已存预警后采样点，展示采样最高/最低相对首次价变化和首次观测低于首次价的时间。同一时点价格冲突不用于轨迹统计；不把全天最高价当预警后极值，不读取统计截止后的点。
- **偏离定位**：有先涨后跌的采样证据时标记“冲高回落”。形态分析只使用首次信号之后且上海时间15:00之前的采样；收盘同刻/之后的记录不能用来证明较早收盘前的先后顺序。原始记录和独立收盘证据保留。两分钟采样不能精确定位首次跌破时刻或真实极值。
- **原因核查**：下跌时列出价格强势失效、市场/板块同步变化、事件风险三个待核查方向及所缺证据。不是已证实的原因，不给编造的置信度。
- **报告摘要**：有效收盘上涨/下跌/持平/未知数量及核查建议；不混用盘中下跌和收盘失败，不把价格表现叫交易盈利率。单日不能证实策略优劣。
- **V1次日分析**：新增独立 `next_day_analysis` / `next_day_analysis_summary`，股票行内、日报/周报可读取次日偏离形态与待核查原因。事实引用原始证据编号，识别反弹未保持、最高价未收回推荐价、收盘跌破原低点，并区分推荐价与推荐日收盘两种比较基准；基于未舍入价格分类。缺证据/来源冲突不生成下跌解释，不使用原模拟退出和推荐当日采样推断次日走势。真实因果仍未核验，分钟量价/板块时序/事件来源与公司行为可比性仍有缺口。[模块与验收边界](reviews/2026-09-09-v1-next-day-analysis.md)。
- **V1结果口径**：原次日规则记录按首次批次和股票只读关联，缺实际交易日与历史入库时间核验，覆盖数量不是胜率。`next_day_close` / `next_day_metrics` 按2026年沪深已公布交易安排关联目标日收盘，单列有效分母/未知/覆盖率，不混入推荐当日指标或原模拟净收益。日历来源及局限见[核验记录](reviews/2026-09-09-next-session-calendar.md)。
- 旧归档保持原样；没有解释字段的历史快照提示“尚无逐股分析”。重新生成相同区间会创建包含新分析的新修订。
