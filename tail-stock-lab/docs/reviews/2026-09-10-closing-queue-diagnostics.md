# 收盘补采队列只读诊断

状态：后端实现、离线回归与服务器真实队列只读验证完成；**本批 API 尚未发布，网页诊断面板尚未实现**。2026-09-10。

## 已实现

- `GET /api/review/collection/jobs`：按股票代码、目标日期区间、原始状态查询，返回有上限的分页、匹配总数及同过滤条件下的状态计数。计数不是当前页计数。
- `GET /api/review/collection/attempts`：按目标日期、股票、提供方三元组读取尝试时间线和当前队列状态。失败后成功不会抹去失败；不同提供方不混为一条记录。
- 读取独立 `review_collection.db`，使用 SQLite `mode=ro` 和单请求读事务；不创建缺失库、不初始化队列、不调用行情提供方、不领取租约、不触发重试或重采。
- 对外字段白名单隐藏 `lease_token`、`attempt_id`。失败仅返回已经记录的异常类别，不返回运输异常正文、文件路径或堆栈。无法打开或不兼容的数据库返回 503，不能冒充空队列。

## 查询契约

`jobs` 可选参数：`date_from` 与 `date_to` 必须同时提供，范围有序且最多 366 天，年份 1900–9998；`code` 为六位 ASCII 数字；`status` 仅接受 `pending/running/failed/completed`。默认 `limit=50`，上限 200；`offset` 范围 0–1000000。

```text
GET /api/review/collection/jobs?date_from=2026-09-01&date_to=2026-09-09&status=failed&limit=50&offset=0
GET /api/review/collection/attempts?trade_date=2026-09-04&code=000001&provider=<jobs返回的provider>&limit=50
```

列表按目标日期倒序、代码及提供方升序；尝试历史按持久化序号倒序。响应包含 `as_of`、`queue_status`、`items`、`total`、`limit`、`offset`、`next_offset`。不存在队列时 `queue_status=not_initialized`，不能解释为所有数据已齐。

每次请求内部保持同一读取快照；**跨页并不冻结整个队列**。采集过程中状态会变化，刷新过滤条件应回到第一页。日期指实际补采目标日，可能是推荐日，也可能是 V1 次日；队列按股票/日期/来源复用，不伪造策略归属。

## 状态含义

| availability | 含义 |
| --- | --- |
| completed | 本采集任务已完成；不代表真实涨停价、触板顺序等全部证据已齐 |
| awaiting_close | 尚未到目标日 16:00 的日线补采允许时间 |
| cooldown | 已记录下一重试时刻，仍处于失败冷却 |
| running | 租约仍有效，不能由其他工作器重复领取 |
| lease_expired | 已记录租约过期；只读诊断不会自动恢复任务 |
| ready | 当前队列时间条件允许处理；不保证提供方有数据或下一刻立刻执行 |
| unknown | 历史状态不认识、相关时间无时区/缺失/无效，不能猜测已就绪 |

`ready_to_collect` 与 `next_eligible_at` 仅表达现有采集器的时间约束，**不是服务器下一调度时间、采集成功承诺或行情就绪证明**。已完成项默认不再采，显式复核仍使用已有管理员 CLI。未知状态附 `diagnostic_flags`，不改写旧记录。
